# Agent guide: extend content using data

Use the [content contract](content-model.md) and the current owner-approved POL-6 definitions. Real drafts, source texts and review records belong in the [private editorial repository](https://github.com/wmpons-mc/presidentielle-2027-editorial), never in a public branch, PR or preview.

1. **Add an actor.** Append a `person` or `organization` with a new stable ID, version 1 and an initial history event. Keep `editorialState: draft`. Record political candidacy as dated, sourced events; use `unknown` if it is unestablished. `availability` is a separate editorial setting. Do not invent a declaration or treat a party position as an individual position.
2. **Add a topic/question.** Append data records with stable IDs; the question references the topic's exact version. Fill its private meaning, includes, excludes, overlap rules, comparison fields, units and positive/negative/ambiguous examples. Keep the reviewed rubric version. No schema, migration or business-code list changes are needed for compatible additions. For a meaning change, append a question revision with `definition_change`, list affected `reexaminePropositionRefs`, reexamine their classification and evidence, then obtain a new review. Never silently rewrite an existing definition.
3. **Attach evidence once.** Add each source version with author, support type, URL, dates and digest of the collected source artifact. Keep its full text and rights assessment private. Add a canonical citation with actual speaker, exact fragments, page/section/paragraph/time locator and omission flags. A proposition references the author, one or more questions and those citation IDs; do not copy quotation text into every question. Preserve conditions, quantitative dimensions and uncertainty. Record corpus-specific coverage separately.
4. **Validate privately.** Run `npm run validate:content -- /absolute/private/path/snapshot.json` on a trusted machine. Check attribution, locators, source rights and editorial meaning yourself; a passing schema cannot verify those facts. Run `npm run check` for code changes. Do not upload private validation inputs or errors containing source text to public CI.
5. **Obtain exact-version owner approval.** In the private review workflow, prepare the batch and eligible per-record states, compute `snapshotDigest`, and have the owner review that exact batch. Store their identity, timestamp and digest in the protected review store and matching private envelope. Any content/definition/state change requires another digest and review. Never invent an approval, and never use the synthetic test reviewer for real content. The authenticated review integration is POL-16.
6. **Export, then publish through the authorized pipeline.** A trusted caller retrieves the approval independently and calls `exportPublic` with `purpose: 'production'`. Inspect the sanitized result; consumers use `current` for navigation/current propositions and `content` for versioned reference resolution. Only this allowlisted, approved result may cross into the public repository. Publication remains the controlled POL-17 workflow and requires its authorization; this ticket does not deploy anything.

For activation, deactivation or withdrawal, append a consecutive revision with the same ID, previous-version reference and dated reason. Retain old revisions and their proofs. Withdrawn availability requires withdrawn editorial state. Revise/deactivate dependent current records together, or the export will reject their now-unpublishable dependency. Candidacy changes are sourced political events, not a shortcut to deleting evidence.

## Reproduce the data-only extension

`tests/fixtures/base.json` contains one fictional actor, three fictional topics/questions and one proposition linked to two questions through a shared citation. `tests/fixtures/extension.json` adds a second fictional actor and a fourth topic/question plus their source, citation and proposition. Both use `example.org` and invented token policies.

Run `npm test`. The extension test reads both JSON files, appends each collection, validates all relationships and verifies the original records are unchanged. It also validates the original dataset on its own. These fixtures are development data, not editorial examples approved for publication. Production export refuses the fixture marker.
